# 只看一张触觉图像，能估计多大的力？一次十指共享模型的完整实验

2026 年 10 月 27 日 · Sharpa Force Predict 实验记录

一张触觉图像里，究竟包含多少力的信息？这次实验把问题收得很具体：**输入一张原始触觉灰度图，直接输出该手指的三维力 Fx、Fy、Fz。** 不输入 RGB 相机画面、形变图、手指编号，也不输入过去的力值。

在 T-Rex 数据集上，我们用一个 ResNet-50 同时训练左右手的十根手指，并在 546 个独立测试 episode、5,602,300 个图像—力值样本上完成评估。48,000 step 的模型得到 **0.380168 的三维力平均欧氏误差**，三个方向的 R² 分别为 **0.9358、0.9606、0.9723**。

这些结果说明，在本实验的数据划分下，单帧触觉图像已经能够支持有效的力值回归。与此同时，近零力样本占比较高、强接触误差更大、不同手指的改善不一致，决定了我们不能只凭一个总体数字判断模型是否足够好用。

在这些轨迹中，模型能够跟随接触开始、受力平台、局部峰值和卸载过程。例如左侧序列中，接触后的快速上升和随后回落在预测中都能看到；中间序列的持续受力阶段，则能看到预测与真实值之间仍有偏差。

曲线适合观察响应形态；模型在整个测试集上的表现，还需要结合下面的完整统计。

## 十根手指，共用一个模型

数据来自 [T-Rex 数据集](https://huggingface.co/datasets/zekaiwang/trex_dataset)。每个样本由一张触觉图像和同一帧、同一手指的三维力标签组成。输入保持原始 320 × 240 灰度分辨率，像素除以 255，不裁剪、不缩放。

网络结构如下：

```text
原始触觉灰度图：1 × 240 × 320
              ↓
ResNet-50 卷积编码器
              ↓
自适应池化到 4 × 5，再展平
              ↓
40960 → 256 → 128 → 3
              ↓
          Fx、Fy、Fz
```

前两层全连接层后使用 ReLU。模型共有 **34,021,059 个参数**，从头训练，没有加载预训练骨干权重。左右手十根手指共享同一套参数；“不输入手指编号”描述的是模型输入形式，并不意味着已经验证了对新传感器的泛化。

训练时，力标签使用训练集的均值和标准差进行标准化，在标准化空间中计算 SmoothL1 loss。评估时再把预测还原到数据集原始力值尺度。优化器使用 AdamW，学习率为 0.0003，weight decay 为 0.0001，梯度裁剪阈值为 5。

本次配置采用 **FP32**，关闭 AMP、TF32 和激活重计算。全局训练 batch 为 1,024。

## 测试集如何划分，结果如何核验

我们按 episode 划分数据，随机种子为 42，保留每一帧，训练、验证、测试分别包含：

| 集合 | Episode 数 |
|---|---:|
| 训练集 | 4,372 |
| 验证集 | 546 |
| 测试集 | 546 |

三个集合的 episode 不重叠，但**物体可以跨集合出现**。因此，这里测量的是独立 episode 上的表现，不能把它称为“未知物体泛化”。测试集还包含时间上相邻的帧，560 万余个样本也不等于 560 万次相互独立的接触实验。

完整测试共覆盖 5,602,300 个样本，每根手指 560,230 个。评估后，我们核对了每个 `(episode, finger, frame)` 的唯一性和覆盖情况，并将全部真实值与缓存标签逐项校验，避免把漏帧、重复帧或标签错位混进最终指标。

除了汇总 JSON 和逐手指表格，完整实验归档还保留了所有逐帧预测，以及 **546 份 episode PDF**：每份同时画出十根手指、三个力轴的时间曲线。公开仓库保留完整聚合指标、逐 episode 指标和展示曲线的数值数据。

## 48,000 step 的完整测试结果

| 指标 | Fx | Fy | Fz |
|---|---:|---:|---:|
| MAE | 0.183249 | 0.177801 | 0.210278 |
| RMSE | 0.447859 | 0.458696 | 0.545102 |
| R² | 0.935767 | 0.960564 | 0.972265 |
| Pearson 相关系数 | 0.967776 | 0.980195 | 0.986045 |

三维力平均欧氏误差为 **0.380168**。它的计算方式是：先对每个样本计算预测向量与真实向量之间的欧氏距离，再对所有样本求平均。

```text
单个样本的向量误差 = sqrt((预测Fx−真实Fx)²
                         + (预测Fy−真实Fy)²
                         + (预测Fz−真实Fz)²)
```

这与“三个方向 MAE 的简单平均”是不同的量。R² 和相关系数也不等于“预测准确率”。本文的力值均使用**数据集原始单位**，尚未独立验证 SI 单位标定，因此不把误差直接标成牛顿。

## 从 40,000 到 48,000：整体改善，但不是全面改善

两次评估使用同一份 manifest 和完整测试集，能够直接比较相同指标：

| 指标 | 40,000 step | 48,000 step | 相对变化 |
|---|---:|---:|---:|
| 平均向量误差 | 0.392341 | 0.380168 | **−3.10%** |
| Fx MAE | 0.180040 | 0.183249 | +1.78% |
| Fy MAE | 0.188406 | 0.177801 | **−5.63%** |
| Fz MAE | 0.222573 | 0.210278 | **−5.52%** |
| 向量误差中位数 | 0.074117 | 0.079404 | +7.13% |
| 向量误差 P90 | 1.221365 | 1.147964 | −6.01% |
| 向量误差 P95 | 1.899382 | 1.829588 | −3.67% |

48,000 step 的平均向量误差下降了 3.10%，三个方向的 RMSE 和 R² 也都改善。但 Fx MAE 上升，中位误差同样上升。这意味着我们看到的是误差分布发生变化，而不是所有样本都变得更准确。

按手指拆开看，十根手指中有七根的平均向量误差下降，左食指、右食指和右无名指上升。左拇指改善约 8.18%，但它的平均向量误差仍高于多根其他手指。更长时间训练带来的收益，需要分轴、分手指和分受力范围一起看。

这些比较是本次实验的点估计，没有提供置信区间，也不是多随机种子重复实验的结论。完整数值保存在[对比文件](../../results/step48000/comparison_step40000_step48000.json)中。

## 为什么还要单独看非近零力和大力值

测试集中，约 **69.68%** 的样本满足真实力向量模长小于 0.1。大量近零力样本会显著影响总体平均误差，因此需要把受力范围拆开：

| 子集 | 样本数 | 40,000 step 平均向量误差 | 48,000 step 平均向量误差 |
|---|---:|---:|---:|
| 近零力 | 3,903,723 | 0.092875 | 0.091471 |
| 非近零力 | 1,698,577 | 1.080582 | 1.043660 |
| 大力值 | 552,703 | 1.870260 | 1.835481 |

非近零力指真实力模长 ≥ 0.1；大力值指模长 ≥ 7.187729，该阈值来自训练集力模长的第 90 百分位。大力值子集包含在非近零力子集中，不能把两行样本数相加。

两类受力子集的误差都有下降，但仍明显高于近零力部分。与之对照，在完整测试集上始终预测零向量的基线，平均向量误差为 1.660094，远高于模型的 0.380168。这说明模型相对零预测基线学到了有效信息，同时也说明“总体误差较低”和“强接触预测已经足够精确”是两个需要分别验证的问题。

## 一次断点恢复带来的工程细节

这次 48,000 step 的 checkpoint 有一段必须讲清楚的来历：原运行按固定间隔保存权重，没有留下 48,000 step 的文件。因此，最终测试使用的模型是**从已保存的 45,000 step 断点重放训练到 48,000 step 后，重新保存并完成完整测试的版本**。

恢复训练不只是读取模型参数。为了从下一批未消费的数据继续，需要一并恢复优化器、随机数状态、数据加载器游标、worker 状态和 shuffle buffer。只恢复权重、再从 epoch 开头读数据，会改变后续实际消费的样本序列。

重放阶段使用单卡，但保留全局 batch 1,024，将它拆成两个 microbatch 512 做梯度累积。这里还有一个容易忽略的细节：普通梯度累积会让 BatchNorm 的运行统计更新两次；此前两卡 DataParallel 的运行统计则由主副本保留。本实现只持久化第一个 microbatch 的 BatchNorm 缓冲区更新，使这一行为与此前主副本的语义对应。

这仍然**不保证 CUDA 运算与已丢弃的原运行逐位一致**。数据位置的连续性、优化器状态的恢复，以及浮点计算的逐位复现，是不同层面的要求。

代码新增了 `--stop-at-step`，可以在指定 step 保存完整断点并退出，即使该步不在常规保存间隔上。相关梯度累积、数据游标恢复和精确停止逻辑已包含在测试中；本次发布的 14 项测试全部通过。

## 如何使用这份开源实现

代码、数据准备流程、训练与评估入口均已发布在 [sharpa-force-predict](https://github.com/itisfree/sharpa-force-predict)。可以先安装并运行测试：

```bash
git clone https://github.com/itisfree/sharpa-force-predict.git
cd sharpa-force-predict
python -m pip install -e .
python -m unittest discover -s tests -v
```

即使没有训练权重，也可以从仓库附带的数值轨迹重新绘制本文的对比图：

```bash
python scripts/plot_examples.py --step 48000
```

训练、断点重放、完整评估和单图推理命令见 [README](../../README.md)。原始数据集由原作者提供，模型权重和大型逐帧预测文件不随 Git 仓库分发；公开内容包含代码、完整聚合指标和展示轨迹，因此需要自行获得可信 checkpoint 才能执行模型推理。

当前结果来自 48,000 step 的中间 checkpoint，并不代表已经完成原计划的 20 个 epoch，也不是依据验证集挑出的最佳模型。下一步值得验证的是：如何改善强接触和较难手指的误差，以及在物体不重叠、新传感器等更严格条件下还能保留多少效果。这些都是后续实验问题，本文不把它们写成已经取得的结果。
